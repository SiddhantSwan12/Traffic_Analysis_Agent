Detection & Tracking of Road Users from Aerial Video

A four-stage pipeline that detects every road user in drone footage, classifies it into seven transport modes, holds a stable identity through occlusion and crossing paths, and suppresses stationary vehicles.

Dataset  Intersection_1080p Frames  11,971 @ 29.97 fps Duration  6 min 39 s Resolution  1920 × 1080 Altitude  ~70 m AGL Gimbal  −63° oblique

Objective

Process drone-captured traffic video and produce an annotated output plus structured per-frame data. The brief set four requirements, all of which had to hold simultaneously:

  1. Classify every road user into one of seven modes — car, LGV, HGV, bus, truck, motorcycle, pedestrian.
  2. Hold a stable identity through occlusion, crossing paths, and long dwell times.
  3. Exclude stationary vehicles from the output.
  4. Draw motion trails for moving objects and a persistent visible ID on each.

The output CSV carries 2,005,350 rows — one per object per frame — of which 76,634 (3.8%) were reconstructed by interpolation across short occlusions. Median track lifetime is 49.9 s and the 90th percentile is 226.7 s, meaning identities routinely survive several minutes of continuous traffic.

Pipeline architecture

Four stages, each caching its output to disk so any stage can be re-tuned without repeating the ones before it. Re-running tracking skips detection entirely; re-rendering skips both.

Detection

The detector is a VisDrone-finetuned YOLOv8-m. At 70 m altitude, objects occupy 11–70 pixels, so a single full-frame pass loses most of them. Two decisions drive detection quality:

Every frame is processed

An earlier approach sampled every fifth frame and held the previous boxes in between, which produced visible lag and flicker. More importantly, it starved the tracker: association quality depends on dense temporal sampling far more than on raw detector strength. Processing all 11,971 frames removed both problems.

Tiles are batched, and deduplicated by geometry

Each frame is cut into eight 640-pixel tiles with 200 pixels of overlap, and all eight are pushed through the network in a single batched forward pass rather than sequentially. Duplicate detections in overlap regions are not removed by non-maximum suppression heuristics. Instead each tile owns an exclusive core region, taken as the midpoints of consecutive overlaps, and a detection is kept only from the tile whose core contains its centre.

Because the overlap is larger than the biggest object in the scene, an object whose centre falls in a core is provably contained whole within that tile. The cores partition the frame exactly once — a property asserted in the test suite. Cross-tile duplicates therefore cannot occur by construction.

Detector confidence is set deliberately low, at 0.15. Recall is cheap and the tracker is the real filter; weak detections feed the second association stage, which is what keeps a partially occluded vehicle alive.

Classification into seven modes

The detector emits VisDrone's ten labels, which do not match the seven required modes. Pedestrian and vehicle categories map directly. LGV and HGV, however, are weight classes that no detector can read from appearance in an overhead view — they must be inferred from physical size.

Calibrating pixels to metres

Metres-per-pixel is recovered from the apparent size of cars, whose real length is known to be about 4.3 m. Because the gimbal sits at −63°, the view is oblique and scale varies down the frame, so a single global scalar would be wrong. The system fits apparent car length against image row and inverts it, producing a scale that varies with position.

The length estimate uses max(width, height) of the axis-aligned box. This is deliberate: for a 4.3 × 1.8 m rectangle, that quantity stays within roughly 1% of 4.3 m at every rotation angle, which makes it an unusually stable ruler regardless of which way a vehicle is pointing.

On this dataset the fit used 481,181 car observations and resolved to 0.128 m/px at the top of the frame and 0.070 m/px at the bottom — a clean perspective gradient consistent with the recorded gimbal angle. The same model yields speed in km/h.

Class is decided per track, not per frame

Each track accumulates a confidence-weighted vote across its entire history, and the winning mode is applied to every frame of that track. This eliminates the label flickering between car, van and truck that per-frame classification produces, and it makes the size refinement far more reliable, since it operates on a track's median length rather than one noisy measurement.

Tracking

The tracker is implemented directly rather than delegated to an off-the-shelf library, which gave full control over the three identity requirements and avoided the API churn that had previously cost time.

RequirementMechanism
Through occlusion Unmatched tracks continue to be Kalman-predicted and stay eligible for matching for 90 frames. Beyond that they move to a long-term gallery, kept for 20 s and recovered on appearance plus a spatial gate. Gaps of 30 frames or fewer are filled by interpolation so boxes never blink.
Through crossing paths Association fuses IoU with a 124-dimension colour and layout descriptor, updated per track, plus a soft penalty for matching across transport modes. Two vehicles that overlap for several frames remain separable by appearance when geometry alone is ambiguous.
Through long dwell No special case is needed. A stopped vehicle is still detected every frame, so it stays matched by overlap while its estimated velocity decays to zero. No timeout applies while it remains visible.

Camera-motion compensation

Even in a stationary hover the gimbal continuously micro-corrects. Left uncompensated, the Kalman filter absorbs that drift as genuine object velocity and mispredicts every box in the frame simultaneously — the single largest source of identity switches in dense overhead scenes. Each frame, a RANSAC affine transform is fitted to background optical flow with all detections masked out, and every track state is warped by it.

Suppressing stationary vehicles

A track is classified as parked, and hidden, only when all four conditions hold at once: it has existed for at least 3 s, exceeded 0.7 m/s in fewer than 5% of its frames, has net displacement under 2.5 m, and never covered more than 3 m within any sliding 10-second window.

Requiring all four is what separates parked from waiting. A vehicle halted at a signal for 90 s still travels a long way before and after the stop, so it stays visible with its identity intact — which the brief explicitly requires.

This also removes static false positives automatically. A detector hallucinating vehicles on a building facade produces perfectly stationary tracks, which satisfy all four conditions and disappear. The earlier approach used a hand-drawn exclusion rectangle for this, which had to be recalibrated for every camera angle and, on inspection, was deleting real vehicles travelling on a road inside its bounds. No manual mask is used anywhere in the current system.

Validation

A synthetic test suite of 30 checks runs without a GPU or the source video. It constructs a scene containing two objects crossing head-on at nearly the same image row, an object hidden for 21 frames, an object hidden for 121 frames that reappears roughly 600 px away, a parked object, and a static false positive — then asserts one stable identity per object, correct parked flags, plausible speeds, and that the tile cores partition the frame exactly once.

Validation caught two defects that would otherwise have shipped:

Defect 1 — rectified jitter read as motion

Speed was computed as the mean of frame-to-frame displacement magnitudes. Box jitter is zero-mean, but taking the magnitude before averaging rectifies that noise into a positive bias, so genuinely static objects appeared to move at around 4 km/h and leaked past the parked filter. Speed is now measured as displacement across a ±7-frame window, which cancels the noise instead of accumulating it.

Defect 2 — a duration-dependent threshold

The parked test required total path length below 6 m. Path length grows with track lifetime, so residual sub-pixel jitter accumulated to 55–67 m across a 400-second track, making the condition impossible for any long-lived parked vehicle to satisfy. Eight cars that never moved more than 1.1 m across the entire video were being drawn as moving traffic. The criterion was replaced with maximum displacement over a sliding 10-second window, which is independent of track duration.

Both were found by inspecting per-track statistics and rendered frames rather than trusting the summary counts, which looked plausible in both cases.

# full pass
python run.py --video Dataset_Video/Intersection_1080p.MP4

# re-tune tracking without re-running detection
python run.py --video Dataset_Video/Intersection_1080p.MP4 --from-detections

# re-render only
python run.py --video Dataset_Video/Intersection_1080p.MP4 --render-only

Limitations and next steps

  • Motorcycle dominance. Two-wheelers account for 469 of 942 moving road users. This is plausible for the location, but VisDrone's motor class is broad and no ground truth was available to confirm the split.
  • Residual slow tracks. Roughly 24 tracks, about 2.5%, sit near the parked boundary. Tightening the thresholds further would begin hiding genuinely waiting vehicles, which is the more damaging error under this brief.
  • No quantitative accuracy figures. The dataset ships without annotations, so MOTA, IDF1 and classification accuracy cannot be reported. All validation is synthetic or visual.
  • Second video pending. The pipeline requires no per-camera calibration, so the Multi_Road sequence runs with a single command change once its 1080p export is available.
